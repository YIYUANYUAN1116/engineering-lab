# UB 内存模型

## 1. 文档目标

区分协议内存语义、OS 内存管理和 UBS Mem 高阶服务。

## 2. 主要来源

基础规范 §8.2、§9、§11.4；OS 参考设计 §4；高阶服务参考设计 §4。[规范确认] [参考设计确认]

## 3. 核心概念

| 层次 | 能力 | 证据 |
| --- | --- | --- |
| 基础协议 | Home-User、UBMD、同步/异步 Read/Write/Atomic、UMMU 翻译与权限、Ownership 框架 | 基础规范 §8-9 |
| OS Component | EXPORT/IMPORT、NUMA/char device 上线、USVA/KSVA/DMA、软件 Ownership | OS 参考设计 §4 |
| UBS Mem | MemFabric、SHMEM、MemCache、MemStore 服务 | 高阶服务参考设计 §4 |

## 4. 架构或机制

内存段由 Home 创建并以 EID/TokenID/UBA 描述；User 可映射后同步或异步访问，也可不映射而仅异步访问。[规范确认] 来源：基础规范 §8.2.1，PDF 第 244-245 页。

规范区分借用与共享：借用时某内存段仅由一个借用方访问；共享时可由多个使用方访问。Cacheable 共享需要一致性维护，规范提供 Ownership 概念但不规定其必须由硬件还是软件实现。[规范确认] 来源：基础规范 §8.2.6，PDF 第 251-254 页。

OS 参考实现的 Ownership 状态为 Invalid/Write/Read，通过 Clean/Invalidate 转移，要求用户保证同一时刻只有一个写者并在读写前后维护状态。[参考设计确认] 来源：OS 参考设计 §4.3.2，PDF 第 20-22 页。

## 5. 关键对象与关系

- 内存注册/导出：USVA、KSVA、DMA 或 EXPORT 形成访问描述；libummu/ummu-core/driver 管理 TokenID、权限表及硬件交互。[参考设计确认] 来源：OS 参考设计 §4.2，PDF 第 18-19 页。
- 生命周期：创建/注册 → 安全交换描述符 → 导入/映射 → 访问与 Ownership 维护 → 等待残留事务完成 → 删除/回收。[规范确认] [基于文档归纳] 来源：基础规范 §8.2.1、§8.2.4-8.2.6，PDF 第 244-254 页。
- 原子性：基础规范定义 Atomic 操作必须只执行一次，并列出交换、算术和逻辑子类型。[规范确认] 来源：基础规范 §7.4.2.3，PDF 第 234-238 页。
- 故障恢复：OS 参考设计区分 Home/User 侧故障，上报给 APEI/OBMM/sysSentry/UBPRM 等，并给出隔离建议。[参考设计确认] 来源：OS 参考设计 §7.3.2、§7.4.2，PDF 第 51-52、55 页。

## 6. 文档明确结论

UBS Mem 的 MemCache 是弱一致缓存服务参考能力，MemStore 是强一致/可靠内存存储服务参考能力；这不改变基础协议和 OS 内存管理的边界。[参考设计确认] 来源：高阶服务参考设计 §4.1-4.3，PDF 第 13-15 页。
