# UB 概览

## 1. 文档目标

回答 UB 是什么、解决什么问题、面向什么系统形态，以及它与常见互联概念的文档内关系。

## 2. 主要来源

基础规范 §2；白皮书 §1-2、§4；OS 参考设计 §1-2；高阶服务参考设计 §2。[规范确认] [白皮书确认] [参考设计确认]

## 3. 核心概念

- UB 面向超节点，把 I/O、内存访问和各类处理单元通信统一到同一互联技术体系。[规范确认] 来源：基础规范 §2.1，PDF 第 13 页 / 正文第 13 页。
- 超节点参考架构支持 CPU、NPU、GPU、MEM、DPU、SSU、Switch 中一种或多种组件池化和平等协同，逻辑上构成一台计算机。[白皮书确认] 来源：白皮书 §2，PDF 第 5 页。
- UB 在超节点中是基础互联协议，不等于超节点整体，也不等于 OS 组件或 Service Core。[基于文档归纳]

## 4. 架构或机制

UB 的六项系统特征是协议归一、平等协同、全量池化、全栈协同、任意拓扑和高可用机制；白皮书以近似但面向价值的表述列出总线级互联、协议归一、平等协同、全量池化、大规模组网、高可用性。[文档间存在差异] 来源：基础规范 §2.1，PDF 第 14 页；白皮书 §2，PDF 第 5-7 页。

## 5. 关键对象与关系

- UBPU 是支持 UB 协议栈的处理单元；Controller 执行协议栈；Switch 转发；Link 是点到点连接；Domain 是 UB Link 连成的 UBPU 集合；Fabric 是 Domain 内 Switch 与 Link 的集合；UBoE 用以跨 Domain。[规范确认] 来源：基础规范 §2.1，PDF 第 14 页。
- CPU、加速器、内存、存储和网络设备是可由 UBPU/Entity 表达和互访的系统资源，但 PDF 未规定所有产品必须同时具备这些类型。[基于文档归纳]

### 与普通网络、PCIe、RDMA 的关系

- UB 自身有网络层、路由、多路径与 UBoE，但文档把它定义为“面向超节点的互联协议”，不能简单等同普通网络。[规范确认]
- 白皮书把 UB 与传统数据中心网络进行能力对比；这是白皮书定位/指标陈述，不是“UB 等于或替代所有以太网”的规范结论。[白皮书确认] 来源：白皮书 §2、§4.2，PDF 第 5-6、22-27 页。
- OS 参考设计在 Memory Mgmt 中复用/扩展 Linux DMA/SVA，在 UBS Comm 中提供 RoUB 将 UB 适配到 RDMA Verbs；这说明 UB 可承载或兼容相关软件语义，不等于 UB 就是 RDMA。[参考设计确认] 来源：OS 参考设计 §2、§5.3，PDF 第 10-11、28-34 页；高阶服务参考设计 §5，PDF 第 16-18 页。
- PCIe 仅作为传统单机设备/资源边界的对照出现，四份 PDF 没有给出 UB 与 PCIe 的完整协议等价表。[文档未说明]

## 6. 文档明确结论

### “UB 是什么”（500 字以内）

UB（UnifiedBus，灵衢）是一种面向超节点的分层互联协议。它用统一协议栈承载内存访问、消息、过程调用和资源管理，使 CPU、NPU/GPU、内存、DPU、存储单元和交换组件可在 UB Domain 内按 Entity 身份直接互访，并通过 UMMU 完成内存地址转换与权限校验、通过 UBFM 管理互连/通信/计算资源。UB 提供同步 Load/Store 与异步 URMA 编程模型，并支持 UBoE 跨域承载。UB 是超节点的互联基础；OS Component 负责操作系统使能，Service Core 在其上提供集群级高阶服务，三者不可混称。[规范确认] [基于文档归纳]

PDF 没有提供一张完整的 UB、PCIe、RoCE、InfiniBand、Socket 功能逐项标准对照表。[文档未说明]
